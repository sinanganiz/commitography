# Metric definitions

Governed by ADR-0012 (catalogue), ADR-0020 (pipeline and classification rules),
ADR-0024 (family contract), ADR-0031 (versioning), ADR-0032 (status reporting),
ADR-0053 (cardinality limits).

This document defines every metric the product produces. It is the reference the
report schema and the archetype taxonomy are written against. Every displayed
number must resolve to a definition here (ADR-0032 clause 7).

---

## 1. Shared definitions

These belong to `core` and are used by every family (ADR-0040).

| Term | Definition |
|---|---|
| **Author local time** | Author timestamp shifted by the timezone offset recorded in the commit. All temporal metrics use this. UTC is never used for hour-of-day analysis. |
| **Analysed commit** | A commit that is not a merge (unless merge counting is enabled), whose author is not excluded, and which falls inside the configured date bounds. |
| **Excluded path** | A path matching an exclusion pattern or marked generated by repository attributes. It counts toward a commit's existence but not toward its size. |
| **Effective lines** | Lines added plus lines removed in a commit, counting only non-excluded paths. |
| **Bulk commit** | An analysed commit whose effective lines exceed the outlier threshold (default 10 000). Excluded from line, size, coupling, churn and hotspot metrics. Included in commit counts and temporal metrics. Reported separately. |
| **Tracked text file** | A file present at the analysed commit, not excluded, and not detected as binary. Binary detection: a NUL byte within the first 8 000 bytes. |
| **Recency window** | 30 days by default. The only consumer is work-type classification (ADR-0020 clause 4). |
| **Identity** | A resolved contributor identity after mailmap and configuration resolution. Represented by display name and a stable digest; never a raw address (ADR-0033). |
| **Subject** | The first line of a commit message. **Body** is everything after the first blank line. |
| **Active date** | A local calendar date with at least one analysed commit. |

**Rounding.** All ratios are reported as floating point in the range 0 to 1 with
6 significant digits. Percentages are never stored; they are a presentation
concern.

**Ties.** Where a metric selects a maximum and several candidates tie, the
earliest by author date wins. Where dates also tie, the lexicographically
smallest commit hash wins. This rule exists to keep output deterministic
(ADR-0021).

**Empty populations.** A metric over an empty population is reported as absent
with the family marked `degraded` and reason `empty_population`. It is never
reported as zero (ADR-0032 clause 3).

## 2. `temporal`

**Input:** commit-records. **Namespace:** `temporal`.

| Metric | Definition |
|---|---|
| `hour_histogram` | 24 buckets. Bucket *i* counts analysed commits whose author local hour is *i*. |
| `weekday_histogram` | 7 buckets. Bucket 0 is Monday. |
| `month_histogram` | 12 buckets by author local month. |
| `year_histogram` | One bucket per calendar year between the first and last analysed commit inclusive, including years with zero. |
| `night_ratio` | Share of analysed commits with local hour ≥ 22 or < 6. |
| `early_ratio` | Share with local hour ≥ 5 and < 9. |
| `weekend_ratio` | Share on a local Saturday or Sunday. |
| `office_hours_ratio` | Share on a local Monday–Friday with hour ≥ 9 and < 18. |
| `friday_evening_count` | Count on a local Friday with hour ≥ 17. |
| `regularity` | Share of analysed commits falling in the 6 most active hour buckets. Ranges from 0.25 (uniform) to 1.0 (all within 6 hours). |
| `busiest_day` | Local date with the most analysed commits, with its count. |
| `longest_streak_days` | Longest run of consecutive active dates. |
| `longest_silence_days` | Largest gap in whole days between chronologically adjacent analysed commits. |
| `active_days` | Count of active dates. |
| `commits_per_active_day` | Analysed commits divided by `active_days`. |
| `first_commit_date`, `last_commit_date` | Local dates. |
| `repository_age_days` | Whole days between first and last analysed commit. |
| `span_ratio` | `active_days` divided by `repository_age_days` + 1. Ranges 0 to 1. |

Person scope: every metric above is also computed over the selected identity
set's commits.

## 3. `commit-size`

**Input:** commit-records. **Namespace:** `commit_size`.
Population: analysed, non-bulk commits.

| Metric | Definition |
|---|---|
| `mean_lines`, `median_lines`, `p90_lines` | Over effective lines. |
| `mean_files`, `median_files` | Distinct non-excluded paths touched. |
| `size_buckets` | Counts in effective-line ranges 1–9, 10–49, 50–199, 200–999, 1000+. |
| `small_commit_ratio` | Share with effective lines ≤ 20. |
| `single_file_ratio` | Share touching exactly one non-excluded path. |
| `largest_commit` | Commit hash, date, effective lines, files touched. |
| `bulk_commit_count` | Count of bulk commits. |
| `bulk_commits` | Up to 10 bulk commits by effective lines descending, with hash, date and lines. |
| `addition_ratio` | Lines added divided by effective lines, over the population. |

`addition_ratio` near 1.0 indicates a repository that mostly grows;
near 0.5 indicates one that mostly rewrites.

## 4. `messages`

**Input:** commit-records. **Namespace:** `messages`.

**Conventional commit.** A subject matching
`^(build|chore|ci|docs|feat|fix|perf|refactor|revert|style|test)(\([^)]*\))?!?: .+`

| Metric | Definition |
|---|---|
| `conventional_ratio` | Share of analysed commits whose subject is a conventional commit. |
| `prefix_distribution` | Counts per conventional type. |
| `keyword_distribution` | Counts per class from the ordered keyword rule list below, applied to non-conventional subjects. First match wins. |
| `mean_subject_length`, `median_subject_length` | Characters. |
| `body_ratio` | Share with a non-empty body. |
| `very_short_count` | Subjects of 10 characters or fewer. |
| `longest_message` | Character count, commit hash, date. Message text is not stored. |
| `emoji_ratio` | Share whose subject contains at least one code point in an emoji block. |
| `revert_count` | Subjects matching `^Revert "` or classified `revert`. |
| `fix_typo_count` | Subjects matching a case-insensitive typo pattern. |
| `wip_ratio` | Share matching a work-in-progress pattern. |
| `issue_reference_ratio` | Share whose subject or body contains `#<digits>` or `<UPPERCASE>-<digits>`. |
| `merge_subject_ratio` | Share matching `^Merge `, computed over all commits including merges, for diagnostic purposes. |

**Keyword rules**, ordered, first match wins: `revert`, `merge`, `fix`, `feat`,
`docs`, `test`, `refactor`, `style`, `build`, `ci`, `chore`, `other`. Patterns
live in a version-controlled rules file, not in code.

**Confidence.** When `conventional_ratio` < 0.30, the family is marked
`degraded` with reason `low_classification_confidence`. Keyword classification
of free-form messages is a guess and is reported as one.

**Language.** Keyword rules are English. For a repository whose messages are
predominantly not English, classification accuracy is unknown; this limitation
is stated in the family's method field (ADR-0032 clause 8).

## 5. `files`

**Input:** commit-records. **Namespace:** `files`.

| Metric | Definition |
|---|---|
| `most_modified` | Top 25 non-excluded paths by count of analysed commits touching them. Paths no longer present at the analysed commit remain ranked and are flagged `removed`. |
| `extension_distribution` | Top 20 extensions by touching commit count, and by file count at the analysed commit. |
| `directory_activity` | Directories at depth 1 and depth 2 with at least 10 touching commits, by touching commit count. Limit 50. |
| `oldest_untouched` | Among files present at the analysed commit, the one whose most recent modifying commit is oldest. |
| `head_file_count`, `tracked_text_file_count` | Counts at the analysed commit. |
| `deleted_file_count` | Paths touched by an analysed commit and absent at the analysed commit. |
| `rename_count` | Renames detected by git across analysed commits. |
| `new_file_commits` | Count of analysed commits introducing at least one new non-excluded path. |

## 6. `coupling`

**Input:** commit-records. **Namespace:** `coupling`.

A **pair** is two non-excluded paths changed in the same analysed commit.

| Rule | Value |
|---|---|
| Commits skipped | Those touching more than 50 non-excluded paths |
| Minimum support | 5 commits containing the pair |
| Confidence | `support / min(changes(A), changes(B))` |
| Minimum confidence | 0.5 |
| Reported pairs | Top 200 by support, then confidence |
| `expected` flag | Set when the two paths share a base name after removing one extension or a known test or spec suffix |

| Metric | Definition |
|---|---|
| `pairs` | The qualifying pairs with support, confidence and the `expected` flag. |
| `graph` | Nodes and edges derived from `pairs`, limited to 150 nodes and 400 edges by support descending. Truncation marks the family `degraded` with reason `cardinality_limit`. |
| `coupled_file_ratio` | Share of files at the analysed commit appearing in at least one qualifying pair. |

## 7. `ownership`

**Input:** replay-state. **Namespace:** `ownership`.
Because replay produces complete line ownership (ADR-0020), these metrics are
computed over all tracked text lines. Sampling is not used.

| Metric | Definition |
|---|---|
| `line_count` | Tracked text lines at the analysed commit. |
| `lines_by_identity` | Surviving line count per identity. Top 200 individually, remainder aggregated (ADR-0018 clause 4). |
| `bus_factor` | The smallest number of identities whose combined surviving lines reach 50% of the scope's lines. Computed for the repository and for directories at depth 1 and 2 with at least 10 touching commits. |
| `knowledge_concentration` | Per directory in scope, the share of surviving lines held by its single largest owner. The owner is named only in the person lens or when per-contributor output is enabled. |
| `code_age_distribution` | Count of surviving lines per calendar year of last write. |
| `median_line_age_days` | Median age of surviving lines at the analysed commit. |
| `first_year_survival_ratio` | Share of surviving lines last written in the repository's first calendar year. |
| `orphaned_line_ratio` | Share of surviving lines whose owning identity has no analysed commit in the last 365 days. |
| `directory_ownership` | Per directory in scope, surviving lines by identity, limited to the top 10 identities per directory. |

**Method.** Line ownership is derived by forward replay of diffs, not by
`git blame`. Replay does not reproduce blame's copy and move detection, so a
line relocated by a copy is attributed to the relocating commit. This is stated
in the family's method field, and the divergence is measured against blame on a
fixture (ADR-0019 clause 6).

## 8. `worktype`

**Input:** replay-state. **Namespace:** `worktype`.

Classification rules are defined in ADR-0020 clause 4 and are not restated here.
Population: changed lines in analysed, non-bulk commits, on non-excluded paths.

| Metric | Definition |
|---|---|
| `breakdown` | The two-dimensional editor-by-previous-owner matrix required by ADR-0018, with a class breakdown per cell. Top 200 identities individually, remainder aggregated. |
| `repository_shares` | `new_work`, `rework`, `help_others`, `legacy_refactor` as shares of classified lines. |
| `classified_line_count` | Total lines classified. |
| `recency_window_days` | The window used, echoed for reproducibility. |

Person-scope shares are a projection of `breakdown` over the selected identity
set (ADR-0018 clause 2) and are never recomputed server-side.

## 9. `ai-archaeology`

**Input:** commit-records and replay-state. **Namespace:** `ai_archaeology`.

**Detection.** A commit is **assisted** when it carries a recognised agent
co-author trailer or a recognised agent signature line. Patterns live in a
version-controlled rules file with its own version, echoed in the report. This
is a heuristic over voluntarily emitted markers: a repository using an agent
without trailers is indistinguishable from one using none. The family's method
field states this.

| Metric | Definition |
|---|---|
| `assisted_commit_count`, `assisted_commit_ratio` | Over analysed commits. |
| `tool_distribution` | Assisted commits per recognised tool identifier. |
| `first_assisted_commit_date` | Local date of the earliest assisted analysed commit. |
| `assisted_line_share` | Share of surviving tracked text lines whose authoring commit was assisted. |
| `assisted_mean_lines`, `unassisted_mean_lines` | Mean effective lines, non-bulk, for each population. |
| `assisted_rework_ratio`, `unassisted_rework_ratio` | Share of lines authored by each population that were rewritten within the recency window. |
| `assisted_survival_ratio`, `unassisted_survival_ratio` | Share of lines authored by each population still present at the analysed commit. |
| `assisted_identity_ratio` | Share of identities with at least one assisted commit. |
| `detection_rules_version` | The rules file version used. |

A zero assisted count is a measurement, not an absence: the family is `ok` with
zero values, not `skipped`.

The comparison metrics are the point of this family. An absolute assisted share
says little; the difference in rework and survival between assisted and
unassisted lines is the finding.

## 10. `hotspot`

**Input:** worktree and commit-records. **Namespace:** `hotspot`.

**Complexity proxy.** Language-agnostic, computed per tracked text file:

1. Detect the file's indent unit as the most common positive leading-whitespace
   increment between consecutive non-blank lines. Tabs count as one unit.
2. `indent_depth` for a line is its leading whitespace divided by the indent
   unit, capped at 20.
3. `complexity_proxy` = mean `indent_depth` over non-blank lines, multiplied by
   the base-2 logarithm of the non-blank line count.

No parsing is performed. This is a proxy, not a measurement of quality, and the
family's method field says so.

| Metric | Definition |
|---|---|
| `change_frequency` | Analysed, non-bulk commits touching the file. |
| `complexity_proxy` | As defined above. |
| `hotspot_score` | Product of `change_frequency` and `complexity_proxy`, each min-max normalised across tracked text files to the range 0 to 1. |
| `hotspots` | Top 100 files by `hotspot_score`, with all three values. |
| `churn_files` | Files receiving at least 5 analysed commits within any rolling 30-day window, limit 100. |

Without working tree access, the family is `skipped` with reason
`worktree_unavailable`.

## 11. `static-analysis`

**Input:** worktree. **Namespace:** `static_analysis`.

This family is in scope and is **non-priority** (ADR-0012 clause 2). Until it is
implemented, it is present in every report with status `skipped` and reason
`not_implemented`, per ADR-0032 clause 1. It is never absent.

Its eventual scope is bounded by ADR-0012 clause 3: a metric family declaring
`worktree`, owning its namespace, with no authority to restructure aggregation.
Language-specific parsing, rule engines and quality gates remain out of scope.

## 12. Cardinality limits, collected

Applied in the report, never in the frontend (ADR-0053 clause 3). Exceeding any
of these marks the owning family `degraded` with reason `cardinality_limit`.

| Limit | Value |
|---|---|
| Individually represented identities | 200 |
| Most modified files | 25 |
| Extensions | 20 |
| Directory activity entries | 50 |
| Coupling pairs | 200 |
| Coupling graph nodes / edges | 150 / 400 |
| Identities per directory in `directory_ownership` | 10 |
| Hotspot entries | 100 |
| Churn files | 100 |
| Bulk commits listed | 10 |

## 13. Reason codes

The enumerated set shared by family status and user errors (ADR-0041 clause 7).
A code absent from this section does not exist (ADR-0062 clause 6). Every
backticked token below is a code and nothing else in this section is backticked,
so the set can be read mechanically.

Family status codes, carried by a skipped or degraded family (ADR-0032
clause 2):

`worktree_unavailable`, `not_implemented`, `empty_population`,
`cardinality_limit`, `low_classification_confidence`, `shallow_clone`,
`limit_reached_commits`, `limit_reached_size`, `limit_reached_duration`,
`limit_reached_memory`, `symlink_escaped_root`, `capability_unavailable_in_mode`,
`external_service_unavailable`, `binary_file_skipped`, `history_rewritten`,
`unresolved_identity`.

User error codes, carried by an error that refuses a run or a request
(ADR-0041 clause 2):

| Code | Condition |
|---|---|
| `invalid_invocation` | Mutually exclusive or malformed flags |
| `invalid_configuration` | Configuration unreadable, unparseable, or carrying an invalid value or pattern |
| `git_unavailable` | Git absent from the path, or its version cannot be determined |
| `git_version_unsupported` | Git present but below the required version |
| `path_not_found` | The supplied path does not exist |
| `not_a_repository` | The path exists but is not a repository, or its git directory cannot be resolved |
| `path_outside_allowed_roots` | A supplied path falls outside every allowed root |
| `empty_repository` | The repository contains no commits |
| `year_below_threshold` | The requested year has fewer analysed commits than the minimum |
| `request_too_large` | A request body exceeds the server's cap |

Three pairs are deliberately separate rather than merged:

- `shallow_clone` belongs to both groups. It refuses a run when the override is
  absent, and marks a family degraded when the override is given. The condition
  is one, so the code is one.
- `path_outside_allowed_roots` is a path someone supplied;
  `symlink_escaped_root` is a traversal discovered during analysis. Their
  remedies differ.
- `empty_repository` refuses a run; `empty_population` describes a metric
  computed over an empty set.

## 14. The identities section

The list of resolved contributors the reader selects their own identity from
(ADR-0010 clause 2). It is **not a metric family**: ADR-0024 clause 5 fixes the
family set and this is not in it. It is a top-level section of the report,
`identities`, beside the generation metadata and the resolved configuration. It
carries no version and no status of its own; the document version governs it
(ADR-0031 clause 1). Adding it made the document version 1.1; adding
`source_address_count` and `merge_candidates` made it 1.2.

**Population.** Every identity with at least one analysed commit. An identity
whose commits are all excluded does not appear.

| Field | Definition |
|---|---|
| `id` | The identity's stable digest: the first 16 hexadecimal characters of the SHA-256 of its canonical address, trimmed and lowercased. Stable across repositories for the same address (ADR-0033 clause 4). Absent on the aggregate entry. |
| `display_name` | The identity's resolved name. Never a raw address (ADR-0033 clause 2): where the resolved name is empty or contains an address, and where anonymised output is requested, it is the `id`. On the aggregate entry it states how many identities the entry represents. |
| `first_commit_date`, `last_commit_date` | Local dates of the identity's earliest and latest analysed commits. |
| `commit_count` | The identity's analysed commits. |
| `source_address_count` | The number of distinct addresses, trimmed and lowercased, that the identity's commits record before `.mailmap` and configuration fold them into it, over every commit collected for the analysis, analysed or excluded. The addresses themselves are never exported (ADR-0033 clause 2). On the aggregate entry, the sum over the identities it folds. |
| `merge_candidates` | Suggestions that another individual entry may be the same person (ADR-0010 clause 4), each an object with the other entry's `id` and the `signal` that produced it: `display_name` (identical resolved names after lowercasing and collapsing whitespace), `local_part` (an identical local part of an address that is not a noreply address), or `noreply` (the account name in a GitHub or GitLab noreply address equals the other identity's local part, noreply account name, or display name without spaces). Signals are computed from the raw data of the internal layer (ADR-0033 clause 1) and compare every address of an identity, configured or recorded. Only individual entries are compared, so every `id` named is an entry of the section. Ordered by `id`, then `signal`; a pair connected by two signals appears once per signal, on both entries. Empty where there is none, and absent on the aggregate entry. Nothing applies a suggestion; a person decides. |
| `aggregate` | `true` on the aggregate entry, and absent on every other entry. |

**Ordering.** Individual entries are ordered by `first_commit_date` ascending,
ties broken by `id` ascending (ADR-0009 clause 3: no default ordering by output
volume). The aggregate entry, when present, is last.

**Bound.** The identities with the most analysed commits, up to the
individually represented identities limit of section 12, appear individually
(ADR-0018 clause 4). Ties in commit count are broken by earlier
`first_commit_date`, then by `id`. Every remaining identity folds into one
aggregate entry, whose dates are the earliest and latest of the identities it
folds and whose `commit_count` is their sum.
