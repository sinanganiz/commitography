# ADR-0019: Golden fixtures, invariants and a performance budget

**Status:** Accepted

## Context
Implementation is produced continuously by AI coding agents and reviewed by a
human with limited time. Reading the code is not a viable control. Reading
behaviour changes as a diff is. A metric whose meaning drifts silently is
indistinguishable from a correct one until the output is already wrong, and
under ADR-0017 wrong output is persisted.

## Decision
1. Deterministic fixture repositories MUST be generated by a committed
   generator. Commit hashes, author and committer timestamps, timezone offsets
   and file content MUST be identical on every generation and on every machine.
2. For each fixture, the produced report MUST be committed as a golden file.
   A change in any golden file MUST be part of the same commit as the code
   change that caused it, and the commit message MUST state why the output
   changed.
3. The following invariants MUST be asserted by tests:
   - work-type shares for a subject sum to 100 percent within rounding
     tolerance;
   - no metric value is negative where negative is meaningless;
   - bulk commits are excluded from line, coupling and churn metrics and are
     included in commit and temporal metrics;
   - an incremental analysis result equals a full analysis result (ADR-0017);
   - an identity-merge projection equals full recomputation with identities
     pre-merged (ADR-0018);
   - a report regenerated from the same repository, commit and configuration is
     byte-identical apart from generation metadata (ADR-0021);
   - every archetype defined in the taxonomy is reachable by at least one
     fixture (ADR-0030).
4. A performance budget MUST be enforced in continuous integration against a
   named fixture, covering elapsed analysis time and peak memory. Exceeding the
   budget MUST fail the build.
5. A test MUST assert that the number of git subprocess invocations during a
   full analysis does not grow proportionally to the number of commits.
6. Replay-derived line ownership MUST be compared against `git blame` output on
   a fixture, and the divergence MUST stay below a threshold recorded in the
   test. This exists because replay tracks ownership through diffs and does not
   reproduce blame's copy and move detection.

## Consequences
- A behavioural regression appears as a golden diff rather than as a silent
  change in a number.
- Review can be performed by reading diffs rather than by reading
  implementations.
- Correct-but-pathological implementations, such as one git process per commit,
  fail the build instead of passing unnoticed.

## Out of scope
- Coverage targets and mutation testing are not mandated.

## Assumption
Fixture generation is fully deterministic. If it is not, the golden regime
produces noise and becomes ignored.

## Acceptance criteria
- Two consecutive fixture generations produce identical commit hashes.
- Every invariant in clause 3 exists as a test.
- The performance budget and the subprocess-count test fail the build when
  violated.

## Dependencies
ADR-0017, ADR-0018, ADR-0020, ADR-0021 and ADR-0030 must be implemented before
their corresponding invariants can be asserted.
